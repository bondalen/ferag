## Задача плана (один чат)

Реализовать **отмену задачи загрузки пользователем** (задача 9.14): при предупреждении о риске таймаута пользователь должен иметь возможность сам отменить задачу, не дожидаясь уведомления о превышении лимита. В рамках одного чата — только отмена задачи; лимиты времени, оценка при старте, предупреждение в UI и статистика (9.15–9.17) — в последующих планах.

**Объём:** backend (сохранение celery_task_id, эндпоинт cancel, публикация в Redis), frontend (кнопка «Отменить загрузку» в TaskProgress).

---

## Исходное состояние

- **Загрузка:** `POST /rags/{id}/upload` создаёт UploadCycle и Task, вызывает `send_update_chain()`; `celery_task_id` в Task не сохраняется (цепочка `apply_async()` без сохранения результата).
- **TaskProgress.vue:** подписка на WebSocket `task:{id}`, отображает шаги (status, step, error); кнопки отмены нет.
- **Эндпоинт отмены:** отсутствует.
- **Права:** загрузка — только владелец RAG; по PROJECT-004 отмена — владелец или участник с ролью editor.

См. [PROJECT-004](../project/PROJECT-004.md), разд. 9.1 «Отмена задачи пользователем».

## Шаги

### 1. Backend: сохранение celery_task_id при старте цепочки

- В `celery_sender.send_update_chain`: вызвать `result = chain(...).apply_async()` и вернуть `result.id` (id первой задачи цепочки).
- В роутере `POST /rags/{id}/upload`: после успешного `send_update_chain` получить celery_task_id и обновить запись Task: `task.celery_task_id = celery_task_id`; `db.commit()`.
- **Важно:** при исключении в `send_update_chain` Task уже создан со status=running; при ошибке — обновить status=failed, error=..., как сейчас.

**Файлы:** `code/backend/app/celery_sender.py`, `code/backend/app/routers/rags.py`.

### 2. Backend: эндпоинт POST /tasks/{task_id}/cancel

- Добавить в `code/backend/app/routers/tasks.py` (или в rags — по структуре API) эндпоинт `POST /tasks/{task_id}/cancel`.
- **Проверки:** Task существует; доступ к RAG (через `_can_access_rag`); право отмены — владелец или участник с role=editor (в rags есть `_is_owner`, при необходимости добавить `_can_edit_rag`); Task.status == "running"; Task.celery_task_id не пустой.
- **Действия:** вызвать `app.control.revoke(celery_task_id, terminate=True)` (Celery); обновить Task: status='cancelled', error='Cancelled by user', updated_at=now(); опубликовать в Redis канал `task:{task_id}` сообщение `{"status": "failed", "step": "", "error": "Задача отменена пользователем"}` для немедленного обновления UI по WebSocket.
- **Redis:** backend уже использует `redis_url` для WebSocket-подписок; для публикации при отмене нужен синхронный клиент Redis (или redis.asyncio в async-эндпоинте). Проверить, как main.py подписывается на Redis — использовать тот же URL.

**Файлы:** `code/backend/app/routers/tasks.py`, при необходимости вспомогательный модуль для Redis publish.

### 3. Frontend: API и кнопка «Отменить загрузку»

- Добавить в `code/frontend/src/api/` функцию `cancelTask(taskId: number): Promise<void>` — вызов `POST /tasks/{taskId}/cancel`.
- В **TaskProgress.vue:** при отображаемом прогрессе (steps.length > 0) и отсутствии финального статуса (done/failed) показывать кнопку «Отменить загрузку». По нажатию — вызов `cancelTask`, при успехе — добавить в steps сообщение с status='failed', error='Задача отменена пользователем' (или дождаться WebSocket, который получит публикацию из backend). При ошибке API — показать сообщение об ошибке.
- После перехода в done или failed кнопку не показывать (или делать неактивной).

**Файлы:** `code/frontend/src/api/tasks.ts`, `code/frontend/src/components/TaskProgress.vue`, `code/frontend/src/views/UploadView.vue` (если кнопка логичнее на уровне UploadView — передать taskId и callback).

### 4. Проверка

- Загрузить файл, дождаться начала выполнения (отображается шаг graphrag или schema_induction); нажать «Отменить загрузку». Убедиться: запрос к API успешен; WebSocket получает сообщение failed; UI показывает «Задача отменена пользователем»; Task в БД имеет status=cancelled.
- Проверить, что после done/failed кнопка отмены не отображается.

## Критерии успеха

- При выполняющейся задаче загрузки отображается кнопка «Отменить загрузку».
- По нажатию задача отменяется (Celery revoke), Task в БД — status=cancelled, UI обновляется (WebSocket или ответ API).
- Права: отменить может владелец RAG или участник с ролью editor.
- После завершения задачи (done/failed) кнопка отмены недоступна.
