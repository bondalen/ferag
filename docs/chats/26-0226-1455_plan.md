# Чат 6 — Переход на Quasar, Pinia (расширение), визуализация (подготовка)

**Дата:** 2026-02-26  
**Предшественник:** [26-0222-2025_plan.md](26-0222-2025_plan.md) (сессии диалогов; резюме [26-0222-2025_plan_resume.md](26-0222-2025_plan_resume.md)).  
**Источник:** [PROJECT-005-frontend-visualization](../project/PROJECT-005-frontend-visualization.md) (разд. 2.1 — текущее состояние, разд. 6 — готовность к плану); [PROJECT-004](../project/PROJECT-004.md), разд. 4 и 4.1; [TASKS.md](../tasks/TASKS.md) — задача 9.5, задачи 7.1.1 и 7.1.2.

## Задача плана (один чат)

Перевести фронтенд приложения ferag на целевой стек **Quasar** (UI-компоненты и layout) и расширить использование **Pinia** (store чата/сессий, персист выбранной сессии). Подготовить задел для последующего подключения **WebVOWL** и **Cytoscape.js** (задачи 7.1.1, 7.1.2) — без реализации экранов онтологии и графа в данном чате. В результате: приложение собирается с Quasar, основные экраны используют Quasar-компоненты, состояние диалога (сессии, выбранная сессия) в Pinia с сохранением выбранной сессии после F5.

**Объём одного чата ограничен:** если работ окажется больше, чем можно выполнить в одном чате, оставшиеся этапы выносятся в пункт «Для последующих планов» (см. в конце).

---

## Исходное состояние

- **Каркас:** Vue 3 + Vite, Vue Router, `base: '/ferag/'`.
- **Pinia:** установлена, stores `auth` и `rags`; store для чата/сессий нет; персист не используется.
- **UI:** без Quasar — свои компоненты (NavBar, TaskProgress, MessageBubble), разметка в views.
- **Экраны:** LoginView, RagsView, RagDetailView (вкладки: загрузка, диалог, участники), UploadView, ChatView, MembersView.
- **Сессии диалога:** реализованы на backend и во frontend (панель «Диалоги», CRUD); выбранная сессия после F5 не восстанавливается.

См. [PROJECT-005](../project/PROJECT-005-frontend-visualization.md), разд. 2.1.

## Шаги

### 1. Подключение Quasar

- Установить Quasar (Vite-плагин или Quasar CLI по выбору) в `code/frontend/`, сохранить `base: '/ferag/'`.
- Настроить тему (переменные под ontoline.ru при необходимости).
- Убедиться, что сборка `npm run build` и dev-сервер проходят.

### 2. Базовая оболочка на Quasar

- Перевести корневой layout (App.vue или обёртка) на Quasar (QLayout, QHeader и т.д., либо минимальная обёртка под маршрутизацию).
- Адаптировать NavBar под Quasar-компоненты (или заменить на Quasar toolbar/меню).
- Проверить отображение всех маршрутов (логин, список RAG, детали RAG, загрузка, диалог, участники).

### 3. Поэкранный перенос на Quasar (в объёме одного чата — приоритетные экраны)

- Выбрать порядок экранов (например: LoginView → RagsView → RagDetailView с вкладками → ChatView → UploadView → MembersView).
- Перевести на Quasar-компоненты (формы, кнопки, списки, вкладки, поля ввода) столько экранов, сколько реально умещается в один чат. Минимум: **LoginView**, **RagsView**, **RagDetailView** (вкладки), **ChatView** (панель диалогов и форма) — чтобы основной сценарий (вход → список RAG → диалог) шёл через Quasar.
- Оставшиеся экраны (UploadView, MembersView и др.) при нехватке времени вынести в «Для последующих планов».

### 4. Pinia: store чата/сессий и персист

- Добавить store (например `chat` или `sessions`): список сессий по текущему RAG, выбранная `sessionId`, при необходимости кэш сообщений. Подключить к ChatView вместо локальных `ref` для сессий и выбранной сессии.
- Подключить pinia-plugin-persistedstate (или аналог); сохранять выбранную сессию по `ragId` (например ключ `ferag.chat.sessionByRag` или по задаче 9.5). При открытии диалога восстанавливать выбор из хранилища.
- Убедиться, что после F5 выбранная сессия восстанавливается и сообщения подгружаются для неё.

### 5. Подготовка к WebVOWL и Cytoscape (задел, без реализации экранов)

- Добавить зависимости: WebVOWL (или пакет для встраивания), Cytoscape.js — в `package.json` без обязательного использования в текущих экранах.
- При необходимости завести пустые/заглушки маршрутов или мест под будущие экраны «Онтология» и «Граф знаний» (по задачам 7.1.1, 7.1.2) — по усмотрению, в объёме, не отнимающем основное время у шагов 1–4.

---

## Критерии успеха

- Сборка фронтенда с Quasar проходит; приложение открывается на https://ontoline.ru/ferag/ (после деплоя).
- Сценарий: вход → список RAG → выбор RAG → вкладка «Диалог» — работает; панель «Диалоги» и переключение сессий работают через Quasar-компоненты (или стабильно поверх Quasar-layout).
- Выбранная сессия диалога сохраняется в localStorage и восстанавливается после F5.
- Store чата/сессий в Pinia используется в ChatView; дублирование логики в локальных ref устранено там, где введён store.
