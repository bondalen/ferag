## Задача плана (один чат)

Перевести фронтенд приложения ferag на целевой стек **Quasar** (UI-компоненты и layout) и расширить использование **Pinia** (store чата/сессий, персист выбранной сессии). Подготовить задел для последующего подключения **WebVOWL** и **Cytoscape.js** (задачи 7.1.1, 7.1.2) — без реализации экранов онтологии и графа в данном чате. В результате: приложение собирается с Quasar, основные экраны используют Quasar-компоненты, состояние диалога (сессии, выбранная сессия) в Pinia с сохранением выбранной сессии после F5.

**Объём одного чата ограничен:** если работ окажется больше, чем можно выполнить в одном чате, оставшиеся этапы выносятся в пункт «Для последующих планов» (см. в конце).

## Исходное состояние

- **Каркас:** Vue 3 + Vite, Vue Router, `base: '/ferag/'`.
- **Pinia:** установлена, stores `auth` и `rags`; store для чата/сессий нет; персист не используется.
- **UI:** без Quasar — свои компоненты (NavBar, TaskProgress, MessageBubble), разметка в views.
- **Экраны:** LoginView, RagsView, RagDetailView (вкладки: загрузка, диалог, участники), UploadView, ChatView, MembersView.
- **Сессии диалога:** реализованы на backend и во frontend (панель «Диалоги», CRUD); выбранная сессия после F5 не восстанавливается.

См. [PROJECT-005](../project/PROJECT-005-frontend-visualization.md), разд. 2.1.

## Диагностика ответов RAG (почему «нет информации в контексте»)

Возможные причины:

1. **Retrieval (контекст из графа):** В LLM попадают только сущности и связи из Fuseki (prod-датасет RAG), отобранные по ключевым словам вопроса. Если факт (год основания, Bob Johnson, Fuseki/AGE) не попал в описания сущностей/связей при индексации (GraphRAG → parquet → RDF) или ключевые слова вопроса не совпадают с именами/описаниями в графе — контекст не содержит этого факта, и модель честно отвечает «нет информации».
2. **Модель/промпт:** Контекст содержит нужный факт, но модель его не использует (инструкция, длина контекста и т.п.).

**Как проверить:** скрипт `code/backend/scripts/diagnose_rag_context.py` выводит тот же текст контекста, который уходит в LLM. Запуск из каталога backend:
```bash
cd code/backend && PYTHONPATH=. python scripts/diagnose_rag_context.py --rag-id 26 --question "В каком году был основан ACME?"
```
Если в выводе нет «2010» — причина в retrieval (в графе для этого RAG нет описания с годом или ключевые слова не подтянули нужную сущность). Если «2010» есть — смотреть модель/промпт.

В API при уровне логирования DEBUG в лог пишется начало контекста (до 1200 символов) для каждого запроса чата — можно включить DEBUG и повторить вопрос.

### Результаты проверки скриптом (RAG 26, датасет ferag-00026)

Скрипт запущен для всех семи вопросов из чата. Fuseki доступен.

| Вопрос | Длина контекста | В контексте есть ответ? | Вывод |
|--------|------------------|--------------------------|--------|
| В какой компании работает Alice Smith? | 230 | Да (ACME Corporation) | Retrieval даёт нужную сущность и связь. |
| Но на какой должности? | 547 (fallback) | Частично («software engineer», без «senior») | Нет совпадений по ключевым словам → фиксированная выборка; в графе описание без «senior». |
| Кто такой Bob Johnson? | 547 (fallback) | **Нет** | В датасете только 3 сущности: ALICE_SMITH, ACME_CORPORATION, SAN_FRANCISCO. Bob Johnson при индексации не извлечён. |
| Где штаб-квартира ACME? | 547 | Да (San Francisco) | Контекст достаточен для ответа. |
| В каком году основан ACME? | 547 | **Нет** (нет 2010) | Описание ACME в графе: «company based in San Francisco that specializes in…» — год не попал в описание при индексации. |
| Когда запустили GraphRAG и кто возглавляет? | 547 | **Нет** | Нет сущности «проект GraphRAG», нет января 2024 и Alice как руководителя в описаниях. |
| Какие технологии хранилища (GraphRAG)? | 547 | **Нет** | Fuseki, PostgreSQL, AGE в графе не представлены. |

**Вывод:** причина «нет информации» — **retrieval и содержимое графа**. В prod-датасете для этого RAG всего 3 сущности и 2 связи; описания короткие и не содержат года, технологий, Bob Johnson и проекта GraphRAG. Индексация (GraphRAG → parquet → RDF) извлекла мало сущностей и обрезала/упростила описания.

### Проверка тезиса: потери при загрузке vs работа ответов

**Тезис:** (1) Элементы, ответственные за загрузку информации из текста, сработали неудовлетворительно и потеряли ~80–90% информации. (2) Элементы, отвечающие за формирование ответов на вопросы, работают удовлетворительно.

**Проверка (без изменений кода):**

- **Исходный текст (source.txt):** перечислены персоны (Alice Smith, Bob Johnson), организации (ACME), места (San Francisco, California, New York, London), проект (GraphRAG), технологии (Fuseki, PostgreSQL, AGE), даты (2010, January 2020, January 2024), роли (senior software engineer, leads Knowledge Graph team), факты (500+ сотрудников, офисы, RDFS, entity extraction и т.д.) — порядка **25+ отдельных фактов/сущностей**.

- **Содержимое графа (ferag-00026):** запрос к Fuseki показал **3 сущности** (ALICE_SMITH, ACME_CORPORATION, SAN_FRANCISCO) и **2 связи** с короткими описаниями. В графе **нет:** Bob Johnson, проекта GraphRAG, года 2010, января 2020/2024, Fuseki/PostgreSQL/AGE, «senior», Knowledge Graph team, New York/London, 500 employees и т.д. В описаниях сохранены только урезанные формулировки (например, «software engineer» без «senior», «company based in San Francisco that specializes in artificial intelligence» без года и деталей).

- **Оценка потерь:** из 25+ фактов/сущностей в графе явно представлены по сути 3–5 (Alice, ACME, San Francisco, работа в ACME, базирование в SF). Остальное отсутствует. **Тезис (1) подтверждается:** загрузка (цепочка GraphRAG index → parquet → RDF → merge → staging → approve → prod) сохранила малую долю информации; оценка «80–90% потерь» по объёму фактов/сущностей обоснована.

- **Формирование ответов:** в случаях, когда контекст **содержал** нужный факт (вопросы про компанию Alice и про штаб-квартиру ACME), модель дала корректный ответ (ACME Corporation, Сан-Франциско). В случаях, когда контекст не содержал факта (Bob Johnson, год 2010, GraphRAG, Fuseki/AGE), модель ответила «нет информации в контексте». **Тезис (2) подтверждается:** блок «retrieval по графу + LLM по контексту» ведёт себя удовлетворительно при наличии данных в графе; проблема не в нём, а в том, что в граф попало слишком мало информации при загрузке.

**Итог:** да — причина в неудовлетворительной работе звена загрузки информации из текста (потеря большей части фактов при индексации); звено формирования ответов работает удовлетворительно.

## Устранение ошибок: 401 при «Подтвердить цикл» и проверка Fuseki

**Проверка Fuseki (prod ferag-00026):** Запрос к Fuseki показал, что в prod-датасете RAG 26 по-прежнему только 3 сущности (ACME_CORPORATION, ALICE_SMITH, SAN_FRANCISCO) — те же, что после загрузки source.txt. **Данных из файла test_doc2.txt в Fuseki нет:** цикл загрузки test_doc2 не был подтверждён из‑за 401, поэтому данные из staging в prod не копировались. Чтобы они попали в граф, нужно после повторного входа снова нажать «Подтвердить цикл».

**Предложения по устранению (реализовано в этом чате / на потом):**

1. **401 Unauthorized при истёкшем JWT — сделано в этом чате:**  
   При ответе 401 от API клиент по-прежнему очищает токен в localStorage; дополнительно диспатчится событие `ferag:unauthorized`. В `App.vue` подписка на это событие вызывает `useAuthStore().logout()` и перенаправление на страницу входа с `query.redirect` на текущий путь. В результате при истечении токена (например, через час) следующий запрос (в т.ч. «Подтвердить цикл») не оставляет пользователя в «залогиненном» виде: UI сбрасывается и открывается форма входа; после повторного входа можно снова нажать «Подтвердить цикл».

2. **Увеличить срок жизни JWT (позже):** В backend в `app/config.py` задано `jwt_expire_minutes: int = 60`. При необходимости увеличить (например, до 480 для 8 часов) или реализовать обновление токена (refresh token).

3. **Долгое выполнение цепочки загрузки (позже):** Если от загрузки файла до появления зелёной галочки проходит около часа — это поведение воркера (Celery) и бэкенда. Разбирать логи воркера на стенде, таймауты задач, объём данных и настройки GraphRAG index.
